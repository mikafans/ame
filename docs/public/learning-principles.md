# AME learning principles

AME helps a learner and an authorized agent work on the same learning journey. It does not turn agent guesses, generated text, or test data into claims about what a learner knows.

The machine-readable source for this page is [`learning-contract.json`](/public/learning-contract.json). Agents should read that contract before creating learner state or running a simulation.

## What counts as learning progress

Starting a journey or choosing a catalog set creates a place to learn; it does not say that the learner completed it. A completed session records activity completion. Mastery requires the learner's own graded assessment or reviewed task work. Pending review, abandoned work, generated content, and a practice score do not prove mastery.

## What an agent may and may not do

An authorized agent can inspect the learner's journey, create reviewed source-backed material, help explain a weak topic, and recommend a next step from the learner's owned evidence. It must not invent answers, submit work as the learner, or manufacture completion, evidence, reviews, streaks, or analytics.

## Sources and review

Reviewed material must make its source, version, review state, and applicable licensing or attribution inspectable. A catalog description is a guide, not a substitute for provenance.

## Simulations and fixtures

Test or demonstration data must be explicit fixture state for a dedicated disposable learner. It must never be mixed with a person's learning history or made to look like real mastery or retention.

## How to check a journey

Before acting, inspect the journey's owner, origin, catalog provenance, source and review state, and the evidence that supports any progress signal. A learner and an authorized agent should see the same information after a restart.
