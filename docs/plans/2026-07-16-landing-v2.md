# AME Landing 2.0

## Decision

Adopt PM direction 1a: a product-first public landing page with a black hero,
blue accent, static quiz preview, three product benefits, an agent-resource
strip, FAQ, and a final signup call to action.

The primary audience is learners. Agent support remains a differentiator and a
supporting section, not the first message a new visitor sees.

## Scope

In scope:

- Replace the public `/` page in `web/app/page.tsx`.
- Preserve the existing `/explore`, authentication, and agent-resource routes.
- Add responsive, accessible landing-page sections matching direction 1a.
- Keep the quiz card as a visual product preview; it does not execute a quiz.

Out of scope:

- New API endpoints or adaptive-quiz behavior.
- Redesigning the authenticated learner shell.
- Pricing, payment, analytics, or anonymous quiz infrastructure.

## Product contracts

- Signed-out visitors use the existing login entry point.
- Signed-in visitors are sent to `/explore`.
- The sample-quiz CTA must enter an existing usable flow; it must not be a
  placeholder button.
- Agent links remain `/llms.txt`, `/skill.json`, and `/openapi.yaml`.
- Marketing copy must not claim “no paid tier” or “every feature is free” until
  that claim is reconciled with the repository's premium roles and quotas.
- The page must not repeat unsupported capabilities as if they were guaranteed
  user-facing behavior.

## Acceptance criteria

- A new visitor can understand AME's learner value from the hero alone.
- The hero preview communicates adaptive study without implying live execution.
- Benefits explain adaptive plans, organized question banks, and measurable
  progress.
- Agent support is visible but secondary.
- All CTAs and resource links have real destinations.
- Desktop, tablet, and mobile layouts have no horizontal overflow.
- Keyboard focus, heading hierarchy, color contrast, and reduced-motion behavior
  are acceptable.
- Existing public and authenticated routes continue to work.
