# Plan 6 (2026-05-20): Exams & composition

**Goal:** Exams table, sections, composition endpoint, composition trace persistence. Static + dynamic exam composition both work; pool insufficiency is a 422 with the failing constraint named.

**Spec:** `docs/specs/2026-05-20-harus-platform-design.md` §4.7 (Exam), §4.8 (ExamSection), §6.1 exam surface, §9.3 (Exams screen — UI in Plan 10).

**Prerequisites:** Plan 5 (engine), since exam sessions reuse the session lifecycle and graders.

**Module rule:** `assess` may depend on `engine`, `bank`, `quiz`, `domain`. Reverse forbidden.

---

## Task 1: Schema (migrated in Plan 2)

- [ ] **Step 1:** Confirm `exams` columns: `id, title, course_id, composed_by_user_id, method enum, status enum, open_at, close_at, duration_min, total_points, passing, objectives text[], created_at`. `method ∈ ('manual', 'agent')`.
- [ ] **Step 2:** `exam_sections`: `id, exam_id, title, quiz_id?, weight, items, mix, order_index`. `quiz_id` is null for dynamic sections (drawn from bank).

## Task 2: Composition endpoint

`POST /exams` — body documented in `design/api.md`.

- [ ] **Step 1: Static composition.** All sections reference existing `quiz_id`. Server resolves sections, computes `total_points`, persists.
- [ ] **Step 2: Dynamic composition.** Sections specify `{ cats[], types[], items, weight, mix? }`. Server draws from the item bank to fill `items` per section, respecting tag and type filters.
- [ ] **Step 3: Composition trace.** Persist the resolution: which items were chosen, which constraints fired, which fallbacks were applied. Stored as `exams.composition_trace jsonb` (or a separate `exam_composition_trace` table — decide at impl time).
- [ ] **Step 4: Pool insufficiency.** If a dynamic section cannot be filled, return 422 with `{ error: 'pool_insufficient', section: <id>, requested: N, available: M, missing_constraints: [...] }`. Do NOT silently fill with whatever fits.

## Task 3: HTTP routes (spec §6.1)

| Method | Path                | Tool           | Scope                 |
| ------ | ------------------- | -------------- | --------------------- |
| GET    | `/exams`            | `exam.list`    | `quiz.read`           |
| POST   | `/exams`            | `exam.compose` | `quiz.write`          |
| GET    | `/exams/{id}`       | `exam.get`     | `quiz.read`           |
| GET    | `/exams/{id}/stats` | `exam.stats`   | `stats.read` (Plan 7) |

- [ ] **Step 1:** `GET /exams/{id}` returns `{ exam, sections[], cohortStatus, compositionTrace? }`. `compositionTrace` is gated on the caller having `quiz.write` (i.e. instructor/admin) — learners never see it.
- [ ] **Step 2:** Idempotency middleware on `POST /exams`.

## Task 4: Exam sessions (delegates to engine)

- [ ] **Step 1:** `POST /sessions { examId }` (Plan 5) hydrates per-section composition. If `exam.method == 'agent'`, the session's `affects_rating` is forced false (spec §5.2).
- [ ] **Step 2:** `deadline_at` derives from `exam.duration_min` if set; otherwise unset (timed exam vs untimed).

## Task 5: Tests

- [ ] Static exam: 3 sections, 3 quizzes — compose, get, attempt.
- [ ] Dynamic exam: filter by tag + type — verify composition trace shape.
- [ ] Pool insufficient: 422 with `pool_insufficient` payload.
- [ ] Agent-method exam: session.affects_rating == false.
- [ ] Composition trace hidden from learner caller.
