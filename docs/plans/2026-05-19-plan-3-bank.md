# Plan 3: Question Bank

**Goal:** Implement CRUD operations for questions, tags, and versions. Set up OpenAPI spec generation.

**Prerequisites:** Plan 2 (Schema & Auth) completed.

---

## Task 1: Domain Types (Questions)

- [ ] **Step 1: `domain/question.rs`**
  Define `QuestionKind` (enum: Mcq, FreeText, Cloze).
  Define structs mapping to the payload shapes (`McqPayload`, `FreeTextPayload`, `ClozePayload`). Use `serde_json::Value` or typed enums.
  Define `Question`, `QuestionVersion`, and `Tag`.
- [ ] **Step 2: Add `utoipa` for OpenAPI**
  Add `utoipa` to `Cargo.toml`. Add `#[derive(ToSchema)]` to the structs.

## Task 2: Bank Repository Layer

- [ ] **Step 1: `bank/tags.rs`**
  Implement `get_or_create_tags` (handling the `name = lower(name)` rule).
- [ ] **Step 2: `bank/questions.rs`**
  Implement `create_questions` (batch insert, max 50).
  Implement `update_question` enforcing the versioning rule: if status is `live`, copy current to `question_versions`, bump version, update. If `draft`, just update.
  Implement `archive_question` and `promote_question`.

## Task 3: HTTP Handlers

- [ ] **Step 1: Tag routes (`http/tags.rs`)**
  `GET /tags`
  `POST /tags`
- [ ] **Step 2: Question routes (`http/questions.rs`)**
  `GET /questions` (with filters: tag, status, difficulty range, pagination).
  `GET /questions/:id`
  `POST /questions` (Requires `agent:write-questions` or `human` scope). Apply idempotency middleware.
  `PATCH /questions/:id`
  `POST /questions/:id/promote`
  `POST /questions/:id/archive`
- [ ] **Step 3: Route Wiring**
  Wire these into `api/src/http/mod.rs`.

## Task 4: OpenAPI Generation

- [ ] **Step 1: Setup `utoipa`**
  Create `api/src/http/openapi.rs`. Define `#[openapi(paths(...), components(...))]`.
- [ ] **Step 2: Serve & Export**
  Serve `/openapi.json` from the router.
  Add a cargo test or build script that writes the generated spec to `api/openapi.yaml` and fails if it drifts from the committed file in CI.

## Task 5: Testing

- [ ] **Step 1: Bank logic tests**
  Write tests verifying that editing a `live` question triggers a version bump and populates `question_versions`, while editing a `draft` does not.
- [ ] **Step 2: API tests**
  Write tests covering the `POST /questions` batch insertion.
- [ ] **Step 3: Run `make check`**
